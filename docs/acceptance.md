# 真机验收清单（v0.30.0）

本清单用于「执行人不在开发现场」时也能照着做完验收。每项都写明**操作步骤、预期现象、失败判定**。
所有结果请记录到文末的「验收记录表」；未实际执行的项不要填 PASS。

- 适用版本：`versionName = 0.30.0`（`versionCode = 39`）
- 应用包名：`com.platojobs.pkotlinapp`
- 主界面：`com.platojobs.pkotlinapp.ui.MainActivity`
- 设备详情：`com.platojobs.pkotlinapp.ui.detail.DeviceDetailActivity`

---

## 0. 验收前准备

### 0.1 硬件与系统

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Android 真机 | Android 12+（API 31+） | 需要验证运行时蓝牙权限 |
| Android 16 设备 | API 36 | 仅「Android 16 两个广播」一组需要 |
| BLE 外设 | 至少 1 个可扫描、可连接的 BLE 设备 | 心率带、手环、BLE 温湿度计均可 |
| 可配对外设 | 支持系统蓝牙配对/加密 | 验证 `ACTION_KEY_MISSING` / `ACTION_ENCRYPTION_CHANGE` 需要 |
| 网络 | 手机与 Go 服务同一局域网 | 产品 / 市场 / 同步需要 |

### 0.2 构建与安装

```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

预期：安装成功，桌面出现「BLE 设备面板」。
失败判定：`INSTALL_FAILED_UPDATE_INCOMPATIBLE`（签名不同，先卸载旧包）；或构建失败（见 `docs/troubleshooting.md`）。

### 0.3 后端准备（产品 / 市场 / 同步）

二选一：

1. 本机 Go 服务（推荐）：
   ```bash
   ./scripts/e2e-contract.sh   # 会构建并启动 STORE=fixture 的 PJGoIoT
   ```
   模拟器使用默认 `http://10.0.2.2:8080/`；真机需要把 BASE_URL 改成电脑局域网 IP：
   ```bash
   ./gradlew assembleDebug -PapiBaseUrl=http://192.168.1.10:8080/
   ```
2. 已有 HTTPS 测试环境：`-PapiBaseUrl=https://your-domain/`。

> Debug 构建已允许明文 HTTP（`app/src/debug/AndroidManifest.xml`）；Release 构建不允许明文，必须 HTTPS。

### 0.4 记录基线

```bash
adb shell dumpsys package com.platojobs.pkotlinapp | grep -E "versionName|versionCode"
```

预期：`versionName=0.28.1`、`versionCode=37`。

## 1. 五模块逐页走查

底部导航固定五项：**首页 / 智能 / 产品 / 市场 / 我的**（不再有独立「设备」Tab）。每页都要检查：能进入、不崩溃、无空白页、无假数据，并实测三态（骨架 / 空态 / 错误块）。

### A0 首启引导与权限前置（v0.9.0 新增）

前置：`adb shell pm clear com.platojobs.pkotlinapp`，确保首次启动。

- 步骤：启动应用，观察三步引导与权限弹窗顺序。
- 预期：
  - 首先出现 3 步引导，依次说明蓝牙（扫描发现/连接取数）、通知（阈值告警）、位置（Android 11 及以下的 BLE 扫描限制；Android 12+ 显示「当前系统不需要位置权限」并明确不申请）。
  - 点「跳过」进入首页；杀进程重开不再出现引导（完成状态已持久化）。
  - 清数据后重走：前两步点「继续」不弹系统框；最后一步点「继续」才依次弹出系统权限框（Android 13+ 通知、Android 12+ 附近设备、Android 11- 位置）。
  - 系统框点「拒绝」后展示「部分权限未授予」：三项授权状态、「仅本机可用：无法扫描或连接设备，不能从设备读取实时读数」、系统设置路径提示。
  - 点「打开应用设置」进入本应用详情页；返回后状态自动刷新。
  - 点「先这样使用」进入首页；空态为「还没有设备」+「开始扫描」，无第二套空态文案。
  - 只拒绝通知时仅提示通知不可用，不出现「仅本机可用」。
  - 引导中途按返回键退出，杀进程重开会再次出现（未完成状态不持久化）。
- 失败判定：首启不出现引导；跳过/完成后仍出现；未点「继续」就弹系统框；拒绝后只剩 toast 或空白；空态存在两套文案；返回退出后不再出现。

### A1 首页 Home

- 步骤：冷启动 App，停留在「首页」。
- 预期：
  - 设备以**两列卡片网格**展示，按真实分组分段；卡片含名称、连接/未连接、最近一条读数（等宽数字）、RSSI 信号条；
  - 顶部搜索与排序（最近 / 名称 / 信号 / 添加时间）可用，分组 Chip 来自真实数据；
  - 首卡上方显示「今日告警」真实条数，点击跳转「智能」；
  - 下方「快捷场景」横向卡最多 3 个，点击执行后 toast 显示「执行成功 / 部分成功 / 失败」汇总；
  - 无设备时显示「还没有设备」+「开始扫描」；后端不可用且无本地数据时显示可重试错误块。
- 失败判定：白屏、崩溃、写死设备或假读数、空态按钮无反应、卡片点击不进详情。

### A2 智能 Intelligence

- 步骤：切到「智能」。
- 预期：
  - 「自动化」显示规则列表，可新增（低 RSSI / 断开 / 绑定丢失 / **指标阈值**）、启停、删除；
  - 「推荐规则」入口按真实读数生成模板，点击即落库并出现在规则列表；
  - 「最近触发」显示真实 `RuleEvent`（指标命中含触发值、阈值、单位），无记录时给出真实空文案；
  - 「场景」显示本机场景，带「仅本机」标识，可新建 / 编辑 / 删除 / 一键执行；
  - 首页不再出现规则入口，本页是唯一入口。
- 失败判定：规则操作无效、重复入口、场景执行无反馈、空态缺失。

### A3 产品 Products

- 步骤：切到「产品」；先确保后端可用。
- 预期：
  - 展示型号库（来自 `GET /device-types` + `GET /device-types/{type}/catalog`）：厂商、型号、最新固件版本、GATT 服务；
  - GATT 服务行由代码动态组装（不是静态占位）；catalog 无特征时不出现空的「特征：」行；
  - 后端不可用时显示「加载失败：…」+「重试加载型号库」。
- 失败判定：展示固定假数据、错误时白屏、重试按钮无效。

### A4 市场 Market

- 步骤：切到「市场」。
- 预期：
  - 展示各设备类型的配件（名称、SKU、适用型号、描述）；
  - 页面有「仅展示配件与固件信息，不含交易能力」说明；
  - 无购物车、订单、支付入口；
  - 后端不可用时显示错误空状态 +「重试加载市场数据」。
- 失败判定：出现交易类假功能、错误时崩溃、展示硬编码占位数据。

### A5 我的 Profile

- 步骤：切到「我的」。
- 预期：
  - 同步卡片显示上次同步时间、待同步条数、最近冲突数；
  - 权限自检三项（扫描 / 连接 / 定位）与系统授权状态一致；
  - 扫描日志有真实记录，可清空；
  - 主题切换立即生效并持久化（杀进程重开仍生效）；
  - 版本信息显示「版本 0.10.0」「构建类型：debug」；
  - 同步卡片显示只读的「会话到期：YYYY-MM-DD」（服务端 token TTL 180 天，取 `expiresAt`，无手动修改入口）；
  - 项目仓库链接可打开 GitHub。
- 失败判定：同步卡片空白、权限状态与实际不一致、版本号不是 0.10.0、会话到期缺失或可编辑、主题重启后丢失。

## 2. BLE 扫描 / RSSI / 连接 / 断开规则

### B1 扫描启动与停止

- 步骤：首页点「开始扫描」。
- 预期：
  - 状态变为「正在扫描附近 BLE 设备…」；
  - 列表出现周围 BLE 设备（MAC + RSSI）；
  - 再点「停止扫描」立即停止，状态回到「未在扫描」。
- 失败判定：权限已授予但列表一直为空（确认周围确有 BLE 设备）、按钮文案不切换、停止后仍持续刷新。

### B2 离开页面自动停止

- 步骤：扫描中切到「设备」或其他模块，再回到首页。
- 预期：离开后扫描停止（日志不再增加），回到首页后按权限自动恢复扫描。
- 失败判定：后台一直扫描耗电、回首页后不恢复。

### B3 RSSI 实时性

- 步骤：扫描列表观察某一设备 RSSI；进入详情后用手遮住设备或拉远。
- 预期：
  - 列表 RSSI 随距离变化（例如 -45 dBm → -80 dBm）；
  - 详情页连接后每 2 秒读取一次远端 RSSI（`readRemoteRssi`）；
  - 自绘信号格数随 RSSI 变化（强 / 良好 / 一般 / 较弱）。
- 失败判定：RSSI 永远不变、详情页 RSSI 为 `-- dBm` 且一直不刷新。

### B4 连接与手动断开

- 步骤：首页或设备页点击设备 → 进入详情。
- 预期：
  - 状态依次「正在连接…」→「已连接」；
  - 已连接后显示设备信息（后端可用时）与 RSSI；
  - 点「断开连接」后状态变为「未连接」，RSSI 清空；
  - **不会自动重连**（等待 30 秒仍是「未连接」）。
- 失败判定：一直停在「正在连接…」、断开后自动重连、详情页崩溃。

### B5 断开规则（DISCONNECTED）

- 步骤：设备页「新增规则」→ 类型「设备断开」→ 保存并启用；连接设备后手动断开。
- 预期：「最近触发」新增一条断开事件；60 秒内同一设备重复断开不会刷屏。
- 失败判定：无事件、同一分钟大量重复事件。

### B6 低 RSSI 规则（LOW_RSSI）

- 步骤：新增规则，阈值填 `-40`，启用；首页扫描，把设备移远到 RSSI < -40。
- 预期：「最近触发」出现「RSSI 低于阈值」事件；阈值输入非法（如 `-120`、`abc`）时保存被拦截并提示。
- 失败判定：事件不产生、非法阈值能保存。

### B7 绑定丢失规则（BOND_LOST）

- 步骤：新增「绑定信息丢失」规则并启用；按第 3 节 G1 触发 `ACTION_KEY_MISSING`。
- 预期：除详情页提示外，「最近触发」记录一条绑定丢失事件。
- 失败判定：广播收到但无规则事件（或广播未投递，按 G1 记为 BLOCKED）。

## 3. Android 16 两个广播

> 前提：Android 16（API 36）真机 + 可配对 BLE 外设。
> 这两个广播都是 `@FlaggedApi` 的受保护系统广播，实际投递取决于系统 flag；**未投递时记 BLOCKED，不要记 PASS**。

### G1 `ACTION_KEY_MISSING`（绑定信息丢失）

- 步骤：
  1. 系统蓝牙设置中完成设备配对；
  2. App 内连接该设备并停留在详情页；
  3. 在系统蓝牙设置中「取消配对 / 忘记设备」（保持连接或触发密钥失效）；
  4. 回到 App 观察详情页。
- 预期：
  - 详情页出现「设备绑定信息丢失，请重新配对」提示；
  - 连接状态进入「绑定丢失」，RSSI 清空；
  - 自动重连被禁止（点击连接无效，必须有「已重新配对，重试连接」）；
  - 重新在系统设置配对后，点「已重新配对，重试连接」可再次连接。
- 失败判定：收到广播但未禁止重连、重新配对后无法恢复、App 崩溃。
- 无法投递时：记录 BLOCKED，并注明机型、系统版本、是否开启相关 flag。

### G2 `ACTION_ENCRYPTION_CHANGE`（加密状态变化）

- 步骤：连接一个支持加密的已配对设备，观察详情页「Android 16 安全事件」区块。
- 预期：
  - 初始显示「尚未收到加密状态广播」；
  - 设备建立加密链路后显示「已加密」+「最近一次加密广播：…」；
  - 断开/取消加密后显示「未加密」。
- 失败判定：收到广播但文案不变、时间戳不更新。

## 4. 权限拒绝与受限路径

### P1 首次启动拒绝扫描权限

- 步骤：清数据后首次启动，走完三步引导；在系统权限框点「拒绝」，点「先这样使用」回到首页，再点「开始扫描」。
- 预期：
  - 首页空态为「还没有设备」+「开始扫描」；
  - 扫描前先出现说明弹窗，点「继续」才弹系统框（已拒绝时系统框不再出现）；
  - 状态栏显示「缺少蓝牙或附近设备权限，可在系统设置中开启后重试」；
  - 底部 Snackbar 出现，并带「打开应用设置」按钮；
  - 点按钮直达本应用的系统设置页。
- 失败判定：只有一句 Toast、无设置入口、点击设置无反应。

### P2 从设置恢复权限

- 步骤：在 P1 的设置页手动开启「附近的设备 / 蓝牙」权限，返回 App，再点「开始扫描」。
- 预期：扫描直接开始，不再弹权限框。
- 失败判定：返回后仍提示缺权限、必须杀进程才恢复。

### P3 拒绝连接权限后点击设备

- 步骤：只授予扫描权限、拒绝连接权限；进入「首页」点击已保存设备。
- 预期：Snackbar「缺少蓝牙连接权限，请在系统设置中授权后重试」+「打开应用设置」。
- 失败判定：直接崩溃、无提示、无设置入口。

### P4 「不再询问」后拒绝

- 步骤：连续拒绝两次（或选择「不再询问」），再点扫描。
- 预期：不再弹系统框，仍显示缺权限提示与设置入口。
- 失败判定：系统框无限弹出、无提示。

### P5 Android 11 及以下的定位权限

- 步骤：Android 11（API 30）设备，拒绝定位权限后扫描。
- 预期：「我的 → 权限自检」显示定位权限「未授权」；扫描提示缺权限。
- 失败判定：低版本不申请定位权限、权限自检状态错误。

### P6 蓝牙关闭 / 不支持 BLE

- 步骤：关闭系统蓝牙后点扫描；或在无 BLE 的设备上安装。
- 预期：提示「蓝牙未开启，请先开启蓝牙」或「当前设备不支持 BLE」，不崩溃。
- 失败判定：崩溃、无提示、一直转圈。

## 5. 横屏与大屏

### R1 横屏走查

- 步骤：开启自动旋转，依次旋转五个模块与设备详情。
- 预期：页面重排正常；列表可滚动；无控件被状态栏/导航栏遮挡；无崩溃；输入框（新增规则）不被键盘完全遮挡。
- 失败判定：内容被裁切、白屏、Activity 重建崩溃。

### R2 分屏 / 折叠屏 / 平板

- 步骤：进入分屏或折叠屏展开态；或使用平板。
- 预期：布局随窗口尺寸变化，列表宽度自适应；底部导航仍可用；无固定高度导致的重叠。
- 失败判定：底部导航被挤出屏幕、内容重叠、必须退出分屏才能操作。

### R3 Edge-to-edge

- 步骤：检查首页顶部与底部导航。
- 预期：内容从状态栏下方开始，底部导航不被手势条覆盖。
- 失败判定：文字被状态栏压住、底部按钮点不到。

## 6. 断网与同步降级

### N1 网络页面降级

- 步骤：开启飞行模式，进入「产品」「市场」，再进入任一设备详情。
- 预期：
  - 产品 / 市场显示加载失败 + 重试按钮；
  - 详情页设备信息显示失败提示 +「重试读取设备信息」；
  - 首页 / 设备 / 我的 的本地数据仍正常展示。
- 失败判定：崩溃、白屏、展示假数据。

### N2 同步失败与纯本地模式

- 步骤：断网状态下，在「我的」连续点 3 次「立即同步」。
- 预期：
  - 每次提示「同步失败：网络不可用，请检查网络后重试」；
  - 第 3 次后出现「已连续失败，切换为纯本地模式…」，主界面顶部出现「网络同步不可用…」横幅；
  - 同步卡片显示「最近错误：…」；
  - 本地设备与日志仍可读写。
- 失败判定：无分类文案（直接暴露异常类名）、横幅不出现、断网后本地功能不可用。

### N3 恢复网络后自动重试

- 步骤：保持 App 在前台，关闭飞行模式，等待后台任务重试（指数退避 30 秒起）。
- 预期：同步成功后横幅消失；「上次同步」更新；待上传数下降。
- 失败判定：恢复网络后永远不再同步、必须重装应用。

### N4 登录失效（401）与重新登录

- 步骤：
  1. 后端可用时先完成一次成功同步；
  2. 让服务端 token 失效（重启 `STORE=fixture` 的 Go 服务即可，fixture 数据在内存中）；
  3. 在「我的」点「立即同步」。
- 预期：
  - 同步卡片显示「登录已失效，同步已暂停；本地数据与同步游标仍保留」；
  - 「立即同步」按钮消失，出现「重新登录」按钮；
  - **不会自动换账号重试**；本地设备与日志不受影响；
  - 点「重新登录」弹出确认框，明确提示会以新匿名账号同步、旧账号数据不会被删除或覆盖；
  - 确认后同步成功，同步卡片恢复正常，本机设备被推送到新账号。
- 失败判定：401 后自动重新匿名登录、游标被清空且无提示、本地数据丢失、确认框文案缺失。

### N5 游标失效（410 RESYNC_REQUIRED）与全量重同步

> 需要真 Postgres 栈（fixture 内存存储没有保留期清理）。可先执行 `./scripts/e2e-postgres.sh` 完成自动化验证，再做人工走查。

- 步骤：
  1. 用 `PJGoIoT/scripts/stack-for-e2e.sh` 起栈，App 指向该 `BASE_URL` 完成一次同步，记录本地游标（`adb shell run-as com.platojobs.pkotlinapp ls shared_prefs` 可确认 `sync_prefs`）；
  2. 在 App 内新建一台设备并断开网络，使其保持 `pending`；同时在另一台设备/服务端产生一条新变更；
  3. 用 SQL 把该用户最老 `change_log.seq` 的 `server_ts` 改到 100 天前，运行 `cmd/cleanup`（change_log 保留 90 天）；
  4. 恢复网络，在「我的」点「立即同步」。
- 预期：
  - 同步不再无限重试，只做一次 `cursor=0` 全量拉取；
  - 本地 `pending` 设备与读数仍在，随后被重新上传，待同步数下降；
  - 「我的」同步卡片出现「云端变更记录已过期，已重新全量同步（时间）」，不静默；
  - 之后继续按 `nextCursor` 增量同步，不重复全量。
- 失败判定：收到 410 后进入指数退避/反复重试、游标未归零、pending 被删除、提示缺失、把 410 当 401 要求重登。

### N6 服务端繁忙（503 TIMEOUT）与指数退避

- 步骤：让后端返回 503 `TIMEOUT`（或临时把查询超时压到极短），在「我的」点「立即同步」。
- 预期：
  - 文案为「服务端繁忙，稍后重试」，不是「云端变更记录已过期」，也不弹「重新登录」；
  - 本地游标与 `pending` 保留，后台按指数退避重试；
  - 服务恢复后同步自动成功，无需手动重登或清数据。
- 失败判定：按 410 清空游标并全量重拉、按 401 暂停同步、或直接暴露异常类名。

### N7 设备类型目录改为服务端真值（v0.20.0 新增）

前置：后端 PJGoIoT **v0.19.0**（`GET /api/v1/catalog/device-types` 匿名可读，带 `ETag` / `Last-Modified`）；应用为 `0.20.0`。

- 步骤与预期：
  1. **首屏不被目录卡住**：冷启动进入「产品」与「市场」，本地已有缓存时立即渲染列表与兼容性，目录请求在后台完成，不出现整页 Loading。
  2. **服务端真值**：在产品页任选一个类型进入详情，指标、限制、GATT 服务与「兼容性」文案均与 `curl /api/v1/catalog/device-types` 返回一致；本地没有任何写死清单，修改服务端目录后下拉刷新即可看到新内容。
  3. **条件请求**：首次请求后查看 Room `catalog_sync_state` 的 `etag` / `lastModified`；再次刷新时 `logcat`/抓包应带 `If-None-Match` / `If-Modified-Since`，命中 `304` 时不重写条目，只更新 `lastUsedAt`。
  4. **离线缓存**：有缓存时断网重进产品/市场，仍显示上次目录，并在目录状态行标注「目录更新时间」与离线提示；不得显示空白或假数据。
  5. **无缓存失败**：清除应用数据后断网进入产品页，显示可读网络错误与「重试」，重试可恢复；不得回退到旧写死清单。
  6. **不支持的指标**：目录声明湿度（`2a6f`）或体重（`2a9d`）时，详情与市场兼容性中该指标标注「当前版本不支持」，不得显示为可读取。
- 失败判定：首屏被目录请求阻塞、界面出现本地写死的旧类型/指标、304 时条目被无意义重写、断网无缓存时展示旧清单、未实现指标被当作可读。

### N8 账号与数据（v0.20.0 新增）

前置：后端 PJGoIoT **v0.19.0**（`POST /me/deletion-request` → `DELETE /me`；`POST /me/export` 异步任务）；已登录账号。

- 步骤与预期：
  1. **导出状态**：在「我的 → 账号与数据」点「导出账号数据」，状态依次为「正在请求导出任务…」→「服务端正在生成导出文件…」→「正在下载导出文件…」→「导出完成，可下载」，完成后出现「分享文件」；生成的 JSON 含本人用户、设备、读数聚合、家庭与反馈。
  2. **导出链接时效**：用同一导出文件链接二次下载（或等待超过 10 分钟）得到 410；在应用内重新导出/重试时，客户端会重新查询任务拿新链接，不得复用失效地址。
  3. **删除两次确认 + 令牌**：点「注销账号」先出现第 1 步说明，继续后出现第 2 步最终确认；确认后才请求一次性令牌并删除。只关掉任一对话框都不得发出删除请求。
  4. **409 家庭还有成员**：owner 的家庭仍有其他成员时删除返回 409，界面提示「家庭还有其他成员，请先转让所有权或移除成员」并提供「前往家庭设置」跳转；本地数据不得被清空。
  5. **删除成功**：删除成功后回到未登录态，`Room` 中设备、读数、规则、场景、反馈草稿为空，凭据已清空；重新匿名登录后不复现旧设备与读数。
  6. **网络/令牌失败**：断网或令牌过期（410）时给出可读提示，账号与本地数据保持原样，可重试。
- 失败判定：只有一次确认、无令牌直接删除、409 时清空本地、删除后残留设备/读数/凭据、导出复用失效链接或状态不更新。

### 7.6 设备读数（readings）验收（v0.4.0 新增）

前置：真机 + 至少一台支持以下任一 notify 特征的 BLE 设备（心率 `0x2A37`、电池 `0x2A19`、温度 `0x2A6E`、NUS TX `6E400003-…`）；后端为 PJGoIoT v0.4.0（含 readings 端点）；应用已授予「附近的设备」权限。

- 步骤与预期：
  1. **订阅与采集**：进入设备详情并连接；用 `adb logcat -s BleReadings` 观察，设备真实推送 notify 后应出现解析成功路径的读数，详情「数据」区出现对应指标 Chip；无数据时显示「连接设备后开始采集」，不得出现演示数据。
  2. **解析正确性**：心率带读数与设备屏幕/官方 App 对比误差 ≤1 bpm；电池百分比与系统蓝牙设置中的电量一致；温度计读数与环境温度量级一致；NUS 设备按文本 `metric=value` 解析出正确指标。若无对应特征，该指标 Chip 不应凭空出现。
  3. **非法报文不写脏数据**：用 nRF Connect 发送非数字/超长 NUS 文本或长度不足的报文；`logcat` 出现 `discard invalid reading`，详情页无新增异常值，App 不崩溃、连接不断开。
  4. **本地保留与 pending 保护**：联网同步后把系统时间调快 8 天重开 App，已同步且超过 7 天的读数应被清理、最近 7 天保留；断网产生读数（`syncState=pending`）后同样把时间调快 8 天重开，`sqlite3 ... "SELECT COUNT(*) FROM readings WHERE syncState='pending';"` 必须保持不变，pending 不得被清理。
  5. **同步与幂等**：联网执行「立即同步」，服务端 `GET /api/v1/my/devices/android/{externalId}/readings?limit=100` 返回倒序列表且 id 与本地一致；重复同步同一批不报 409，服务端 `skippedReadings` 增加、列表无重复。
  6. **断网补传**：断网连接设备产生读数（`readings` 表 `syncState=pending`）；恢复网络后同步，`pending` 清零且服务端出现对应读数。
  7. **汇总与离线标注**：`GET .../readings/summary?metric=&hours=24` 的 min/max/avg/last 与详情页汇总行一致；停掉网络/后端后重进详情，仍显示本地图表与最近记录，并出现「离线：本地数据」。
  8. **图表边界**：0 条读数（新设备）显示空状态不崩溃；1 条读数时只画一个桶的区间带与数据点；长周期分桶后折线、坐标轴、首尾时间正常，无越界或闪烁（区间与缺口见 §7.7）。
  9. **权限空状态**：在系统设置撤销「附近的设备」权限后重进详情，「数据」区显示权限提示与「去应用设置」按钮，点击可跳到本应用设置页；恢复权限后读数恢复展示。
- 失败判定：notify 已到达但无读数、读数与真实值明显不符、非法报文导致崩溃或写入脏数据、本地超过 7 天仍保留、重复同步报错/重复插入、断网读数丢失、离线仍显示远端数据、0/1/60 点图表崩溃、无权限时展示假数据或按钮无响应。
- 说明：模拟器无法接收真实 BLE notify，本组必须真机执行；解析器的合法/非法/超长/非数字路径已由 `GattReadingParserTest` 覆盖，同步与查询契约由 e2e 覆盖。

  4. **恢复**：让信号回到阈值内，出现一条「告警已恢复」；再次恢复不会重复出现；恢复后立即再次触发可再次通知。
  5. **开关关闭**：关闭「接收告警通知」，再次制造命中；通知栏无新增，但设备页规则事件仍增加；重新打开开关后新的命中可正常投递。
  6. **拒绝权限**：Android 13+ 拒绝 `POST_NOTIFICATIONS` 后，「我的」出现「系统通知权限未授予」与「去设置授予通知权限」；点击跳应用设置；扫描、连接、同步、图表均不受影响。
  7. **隐私**：通知正文与展开内容不含 token、账号、安装 ID 等敏感字段。
  8. **指标阈值通知（v0.11.0）**：新增「温度 > 30℃」规则并制造真实高温读数；通知正文含设备名、指标名、触发值+℃、比较符、阈值+℃ 与时间；低于阈值后出现一条「已恢复」。
- 失败判定：无渠道、拒绝权限后崩溃或其它功能被阻断、窗口内重复通知、恢复通知重复/缺失、关闭开关仍投递、点击通知进错设备、指标通知缺单位或恢复重复。

### 7.11 账号迁移与注销验收（v0.7.0 新增）

前置：PJGoIoT v0.7.0+（openapi 0.6.0）已启动；准备**两台** Android 设备（旧机 A 与新机 B），两台都安装本版本。

- 步骤与预期：
  1. **生成配对码**：A「我的」→「迁移到新设备」→「生成配对码」；出现 8 位大写码，字符只含 `A-H/J-N/P-Z/2-9`（不会出现 `0/O/1/I`）；倒计时从服务端的 `expiresAt` 开始递减（对照服务端时间，与本地时钟无关）。
  2. **复制**：点「复制」，剪贴板内容为 8 位码，粘贴可原样得到。
  3. **重新生成**：点「重新生成」先弹确认并提示「旧码立即失效」；确认后出现新码。用 B 输入**旧码** → 提示「码无效或已过期」。
  4. **接管**：B「我的」→「从旧设备接管」输入新码。输入框只能输入 8 位、自动大写、输入 `0/O/1/I` 时被过滤、不足 8 位时按钮不可用。提交后提示接管成功并展示 userId；A 上原有数据（设备、读数）在 B 上保留且随后续同步上传到同一账号（服务端按该 userId 可查到）。
  5. **错误处理**：输入过期或已用的码 → 只显示「码无效或已过期」，不出现具体原因；1 分钟内连续错误输入触发限流 → 出现「尝试过于频繁，请稍后再试」，若服务端返回 `Retry-After` 则显示剩余秒数；飞行模式下提交 → 出现网络可重试提示。
  6. **导出我的数据**：A/B 任一「我的」→「导出我的数据」；进度显示「已拉 N 条 / 第 M 页」且 M 随分页递增；`adb shell run-as com.platojobs.pkotlinapp ls cache/exports` 出现 `account_export_<userId>_<UTC>.json`；系统分享面板可打开，JSON 内 `user/devices/readings` 齐全、`readings` 按 `recordedAt` 升序且无重复 id。
  7. **导出失败重试**：停后端后导出 → 出现明确失败提示与「重试」；恢复后端后重试成功。
  8. **注销**：确认对话框必须出现「设备与读数将永久删除且不可恢复」；确认后提示注销成功并回到匿名初始状态（「我的」同步卡片回到初始、设备/读数列表清空）。
  9. **注销后校验**：`GET /api/v1/sync/changes`（旧 token）返回 401；`adb shell run-as com.platojobs.pkotlinapp ls databases` 业务表为空（可 `sqlite3` 检查 `readings`/`devices` 行数，或重启后确认无数据）；再次注销（原 token 已失效）返回 401。
- 失败判定：倒计时用本地时间瞎算、旧码仍可接管、接管后本地数据被清空或仍标记 synced（导致数据不重传）、404 暴露具体原因、429 不显示冷却、导出解析/拼接 cursor 导致漏页、注销后本地仍有业务数据或 token、401/网络错误静默。

### 7.12 后台采集（前台服务）验收（v0.7.0 新增）

前置：至少一台可连接并持续 notify 的 BLE 设备；分别在 **Android 12（API 31/32）**、**Android 13（API 33）**、**Android 14+（API 34/35/36）** 各跑一遍（差异见下）。

- 步骤与预期：
  1. **启动**：连接设备成功 → 详情页出现「后台采集」开关，默认关闭；打开后通知栏出现常驻通知，渠道为 **「数据采集」**（`adb shell dumpsys notification --noredact | grep reading_collection`），标题「正在后台采集」，正文含设备名与「已采集 N 条」，N 随 notify 递增。
  2. **通知动作**：点「停止」→ 服务停止、通知消失、开关自动回到关闭；从最近任务划掉 App 后通知不应长期残留（重新打开「我的」显示未采集）。
  3. **点击通知**：点击通知正文 → 进入该设备详情页。
  4. **持久化**：开关打开后返回列表再进详情、或杀进程后重启 App，开关状态保持（「我的」显示当前是否在后台采集中，含设备名与条数）。
  5. **停止条件**：手动关闭开关 / 断开连接 / 返回退出详情 / 设备进入 `KeyMissing`，四类操作后服务与通知均停止；切到另一台设备并连接时，服务切换到新设备而不是同时采集两台。
  6. **Android 14+ 权限**：检查 `adb shell dumpsys package com.platojobs.pkotlinapp | grep FOREGROUND_SERVICE_CONNECTED_DEVICE` 已授予；手动撤销该权限（`adb shell appops`/设置页）后再打开开关 → 不崩溃，开关回滚并提示启动失败。
  7. **Android 13+ 通知权限**：首次打开开关时请求 `POST_NOTIFICATIONS`。拒绝 → 采集仍启动（「我的」状态显示采集中），界面提示「通知不可见」；允许 → 通知正常常驻。
  8. **Android 12 启动限制**：确认只在详情页（界面可见）点击开关时启动服务；从后台/广播路径不会静默启动（无 `ForegroundServiceStartNotAllowedException`，`logcat | grep BackgroundService` 无相关报错）。
  9. **Android 12 及以下通知渠道**：API 26+ 才有渠道，API 24/25（如可测）不因 `NotificationChannel` 崩溃，通知仍可展示。
- 失败判定：进程被杀即丢通知且状态未持久化、断开后服务/通知残留、Android 12+ 后台启动触发系统异常、Android 14+ 缺权限时崩溃、拒绝通知权限导致功能不可用或崩溃。

4. **未分配分区**：将所有设备移入房间后，「未分配」分区不再出现；任意设备移出后重新出现在最后。
5. **折叠**：点击房间头收起该房间设备，再次点击展开；折叠状态在本次会话内保持；进入搜索后结果不受折叠影响。
6. **删除房间**：删除含设备的「卧室」，确认弹出二次确认且文案写明设备回到未分配；确认后设备出现在「未分配」，房间消失。
7. **空态**：清空所有房间与设备 → 首页显示「还没有房间」+「新建房间」；只保留房间（无设备）→ 首页保留房间分区，房间头提示「该房间暂无设备」，点击进入扫描；搜索无结果 → 显示「没有匹配设备」。
8. **搜索 / 排序 / 分组 Chip 取舍**：搜索设备名时结果平铺且无房间头；排序切换只改变房间内顺序；选中分组 Chip 时只显示含该分组设备的房间，不改变设备所属房间。
9. **删除后落点**：`sqlite3 /tmp/device_dashboard.db "SELECT mac, roomId FROM devices;"` 确认原房间内设备 `roomId` 为 `NULL`。
- 失败判定：房间增删改不同步首页；删除房间后设备消失或仍指向已删房间；未分配未固定最后；搜索仍按房间分段或折叠隐藏结果；空态文案与真实数据不符。

### 7.20 家庭、邀请码、成员共享与权限降级验收（v0.14.0 新增）

前置：后端 PJGoIoT v0.12.0 及以上可用；准备两个可独立登录的客户端（手机 A = 家庭 owner，手机 B = 待加入的 member），两台手机都能访问同一后端。

1. **当前家庭与成员**：手机 A「我的」→ 家庭区显示当前家庭名与角色「所有者」，成员列表含 owner；点击同步后成员数与设备数为服务端真值。
2. **创建家庭**：点「创建家庭」输入名称并确认，提示「已创建家庭：X」，家庭区立即切换为当前家庭。
3. **邀请码**：点「生成邀请码」，显示 8 位一次性码 + 服务端倒计时（分/秒递减）；点「复制」提示已复制；等待倒计时归零后显示「邀请码已过期，请重新生成」，可再次生成新码。
4. **加入家庭**：手机 B「加入家庭」输入小写/带分隔符的邀请码，输入框自动大写并截断 8 位；错误码提示「邀请码无效或已过期」，连续错误提示「尝试次数过多，请稍后再试」；正确码提示「已加入家庭：X」。
5. **首页切换**：手机 B 加入后拥有两个家庭，首页搜索框上方出现横向家庭 Chip（可见，非长按隐藏）；点击切换后设备与房间随家庭变化；手机 A 只有一个家庭时确认不显示切换控件。
6. **成员设备与房间**：手机 B 切到 owner 家庭后能看到 A 的设备，显示真实别名与所属房间；长按该设备提示「家庭成员共享的设备仅可查看，不能修改房间」，详情页改房间同样被拒绝。
7. **权限降级**：手机 B 作为 member 新建/重命名房间时提示「你没有修改该家庭或房间的权限」，列表保持可用，不弹原始 403 码、不整页报错；被移除家庭后访问提示「家庭或房间不存在，可能已被移除」。
8. **房间来源与未同步**：新建房间后若上传失败（可临时断网），房间头显示「未同步」；恢复网络后同步成功，标记消失且服务端房间保留。
9. **离线**：断网进入「我的」与首页，家庭区显示「未同步：当前显示本机缓存，联网后自动更新」，本机房间与设备仍可见，不白屏、不丢数据；恢复网络自动同步。
10. **落库检查**：
    ```bash
    sqlite3 /tmp/device_dashboard.db "SELECT remoteId, name, isPersonal, role, memberCount FROM households;"
    sqlite3 /tmp/device_dashboard.db "SELECT id, name, remoteId, householdId FROM rooms;"
    sqlite3 /tmp/device_dashboard.db "SELECT mac, roomId, householdId, remoteRoomId, pendingRoomPatch, shared FROM devices;"
    ```
    预期：`households.remoteId` 唯一且当前家庭已持久化；远端房间有 `remoteId`，未上传房间为空；共享设备 `shared=1`，待上报设备 `pendingRoomPatch=1`，成功后归零。
- 失败判定：邀请码非 8 位或倒计时不来自服务端；加入家庭未复用配对码规范化；多家庭无切换入口或切换后数据不跟随；member 能改房间/看到原始错误码；离线白屏或本机房间被清空；共享设备可编辑。

### 7.21 家庭管理（成员移除 / 退出 / 邀请码撤销）与房间整段排序验收（v0.15.0 新增）

前置：后端 PJGoIoT v0.13.0 及以上；手机 A = owner，手机 B = member（已加入 A 的家庭并共享设备）；A 家庭至少有 2 个房间。

1. **真实计数**：A、B 的「我的」家庭卡片显示「成员 N · 设备 M · 房间 K」，N/M/K 与 `GET /api/v1/households` 返回值一致；断网后数字仍为上次服务端值，不按本地缓存重新数。
2. **owner / member 入口可见性**：A 能看到「重命名家庭」「生成邀请码」「邀请码列表」「退出家庭」且成员行可长按；B 看不到重命名、邀请码与撤销入口，成员行不可长按，只有「退出家庭」。
3. **邀请码列表**：A 生成一个码后，列表新增一条仅显示哈希前缀（如 `a1b2c3d4`）、状态与过期时间，**不出现 8 位明文**；对着列表项截图与后端 `GET /households/{id}/invitations` 比对，无 `code` 字段。
4. **撤销邀请码**：A 点该行「撤销」，提示成功且该行消失；此时 B（或第三台手机）用该码加入提示「邀请码无效或已过期」。
5. **移除成员**：A 长按 B 的成员行 → 弹出二次确认，文案写明「对方设备将回到其个人家庭」；确认后成员数减 1，B 的设备从 A 的列表消失（共享行清理）。B 再访问该家庭提示「家庭或房间不存在，可能已被移除」。
6. **退出家庭（owner 被拦截）**：A 家庭仍有其他成员时点「退出家庭」，提示「请先转让所有权或移除其他成员」，不发生退出。
7. **退出家庭（成员）**：B 点「退出家庭」并确认，提示成功；B 的设备回落到其个人家庭，家庭内房间清空，B 不再出现在 A 的成员列表。
8. **房间整段排序**：A 在「房间管理」点某行的 ↑/↓ 移动，顺序立即生效并发起整段提交；成功后再进入房间管理顺序保持。
9. **重排冲突**：在另一台设备同时增删房间制造集合变化（或用未包含全部房间的请求复现），重新排序时提示「房间列表已变化，已刷新」，列表自动刷新为服务端最新顺序，不丢失房间。
10. **离线排序**：断网移动房间顺序，顺序本地保留并标记「未同步」；恢复网络同步成功后标记消失。
- 失败判定：邀请码列表出现明文或 `code` 字段；member 能看到签发/撤销/移除/重命名入口；移除成员后对方仍能访问或本机残留共享设备；owner 带成员能直接退出；排序只改本地不提交或 409 后不刷新；计数取自本地缓存。

### 7.22 所有权转让与 isSelf 验收（v0.16.0 新增）

前置：后端 PJGoIoT v0.14.0 及以上；手机 A = owner，手机 B = member（已加入 A 的家庭）。

1. **isSelf 判定**：A、B 分别打开「我的 → 家庭」，各自成员列表中自己的那一行带「（我）」，对方不带；断网重进仍正确（不依赖用户名/id 比对）。
2. **入口可见性**：A 长按 B 行，菜单同时出现「移除成员」「转让所有权」；A 长按自己行无菜单；B 长按任何行都无菜单。
3. **二次确认**：A 选择「转让所有权」，确认文案写明「转让后你降为普通成员，失去修改家庭名、邀请码、移除成员的权限」；取消不发起请求。
4. **成功刷新**：确认后 A 的角色变为 member，重命名/邀请码/成员移除入口消失，只剩「退出家庭」；B 变为 owner，管理入口出现。A 的成员行「（我）」仍正确。
5. **失败处理**：制造 403（B 尝试转让）、404（转让给不存在的 userId）、409（另一设备并发改动成员）时，界面给出可读提示且家庭/成员列表立即刷新到服务端最新状态，不停在旧角色。
6. **老后端降级**：把服务端回退到 v0.13.0（成员列表无 `isSelf`），重进家庭页后不再出现「转让所有权」；若手工触发转让收到 405，只静默刷新，不弹错误框。
- 失败判定：`isSelf` 为真时仍出现移除/转让入口；转让后仍显示管理入口或角色未刷新；403/404/409 无提示或停在旧状态；老后端弹错误。

### 7.23 产品目录与详情验收（v0.16.0 新增）

前置：已登录并完成一次 catalog 同步；「我的设备」中至少有健康类与环境类各一台。

1. **分类导航**：产品页顶部 Chip 显示 全部 / 健康 / 环境 / 网关·中继 / 其他，每组带数量徽标；切到某分类只显示该组条目，徽标数量与条目数一致。
2. **详情分层**：点任一条目进入详情，依次看到设备类型说明、支持指标 Chip、兼容性（平台）、固件版本、GATT 服务与「我的设备」中同 `deviceType` 的条目。
3. **指标真实**：仅展示解析器真正支持的指标（心率 / 电量 / 温度 / NUS）；例如只有电量服务的设备不出现「体重」等未实现指标。
4. **我的设备**：详情页列出的设备与「我的设备」中同 `deviceType` 的条目一致；点击进入现有设备详情。
5. **三态**：断网首次进入产品页显示错误态与重试；空 catalog 显示真实空态；加载时显示现有骨架，不出现第二套三态组件。
- 失败判定：分类数量与条目不符、指标写死假文案、详情「我的设备」与真实归属不一致、空/错/加载态样式与现有 `ThreeStateHost` 不一致。

1. **帮助中心**：进入后 5 个问题可逐条展开/收起；内容覆盖 Transfer Code、连接失败、读数不刷新、同步冲突、退出家庭，且与实际行为一致（owner 带成员退出 409、已同步读数 7 天、冲突以服务端为准）。
2. **意见反馈表单**：可选题型下拉、填写描述、可选联系方式；空描述提交提示「请填写问题描述」。

### 7.25 家庭结构增量同步验收（v0.17.0 新增）

前置：两台设备各有独立账号（A 为 owner、B 为成员），后端为 PJGoIoT v0.15.0（openapi 0.11.0）。

1. **改名 / 建房 / 重排双向可见**：A 在「我的 → 家庭管理」改家庭名、新建两个房间并调整顺序；B 不点手动同步，等待后台同步后确认家庭名、房间名与顺序都更新，且 A/B 看到的成员数一致。
2. **新成员基线**：C 从未加入过，A 签发邀请码、C 领取；C 首次同步后应看到家庭名与全部房间（来自 `GET /households` 全量基线），而不是空房间。
3. **删房不删设备**：A 删除一个房间，B 同步后该房间消失，原房间内设备回到「未分配」且仍可打开详情，设备没有被静默删除。
4. **转让与移除可见性**：A 把所有权转让给 B，双方角色刷新（A 变成员、B 变 owner）；B 移除 A 后再改名，A 的后续同步不再出现该家庭结构变更，但 A 仍能读到离开前的历史（旧家庭名/旧房间），这属正常语义。
5. **未知 entity 不卡同步**：后端新增未知 entity 时（可在测试环境向 `change_log` 插入一条 `automation_rule`），客户端同步仍推进游标，下次同步不会重复卡住；`SyncUnknownEntityTest` 固定该行为。
6. **pending 优先**：离线修改房间名后恢复网络但先别同步，让 A 在另一台设备改名同一房间；本机同步时本地名称与「未同步」标记不被覆盖，联网成功后本地值上传并采用服务端回读值。
7. **410 重拉**：服务端清理过期 change_log 后旧游标返回 `410 RESYNC_REQUIRED`，客户端清游标并 `cursor=0` 全量重拉，pending 房间编辑不丢失。
- 失败判定：未知 entity 卡住游标、删房连带删设备、新成员看不到房间基线、被移除成员仍收到新结构变更、pending 编辑被服务端覆盖、410 后 pending 丢失。

### 7.26 「设备与服务市场」验收（v0.17.0 新增）

1. **无虚构商品**：默认进入「市场」不出现任何商品名、价格、库存、销量；页面只展示兼容性、选购指南与服务入口。
2. **兼容性查询**：选择「Nordic UART」等类型，核对可解析指标、GATT 服务 UUID 与限制文案；指标必须与「产品」页同类型设备的 `ReadingUuids.supported` 一致，NUS 类型提示「设备端需按 `metric=value` 逐行输出」。
3. **选购指南**：三个场景（健康监测 / 环境采集 / 多设备组网）的推荐类型与「依据」来自真实能力；若 catalog 没有匹配类型，界面应如实显示「没有匹配的型号」，不编造推荐。
4. **服务入口**：配对向导打开扫描弹窗；连接排障打开帮助中心对应条目；采集省电跳到「我的」采集卡，三条均不是死链。
5. **示例数据**：打开「显示示例条目」开关后出现条目，每条固定标注「示例数据，不代表真实在售」，且无库存/价格/销量；关闭开关后列表消失，重启 App 仍保持关闭。
6. **三态与无障碍**：断网时走统一错误态并可重试；空 catalog 走空态；200% 字号下 Chip 与卡片换行不截断，开关与卡片触达 ≥48dp，读屏可读出类型与限制。
- 失败判定：出现真实感商品名/价格/库存/销量、指标与产品页不一致、推荐无依据、服务入口死链、示例开关不持久化、加载/空/错误出现第二套组件。

## 10. 已知无法在本仓库内自证的部分

以下结论必须来自真机/真实账号，代码仓库与 CI 只能证明「已实现、能构建、单测通过」：

- 真实 BLE 扫描、RSSI 变化、GATT 连接与断开时序；
- Android 16 两个受保护广播是否实际投递；
- 各厂商 ROM 的权限弹窗行为与设置页跳转；
- Room v1→v2→v3→v4→v5→v6→v7 在真实旧数据上的迁移（本仓库已导出 schema 与 v6→v7 SQLite 迁移测试，但未跑真机迁移）；
- 真实 BLE notify 读数投递与各厂商固件字节格式（心率/电池/温度/NUS 的实际报文需按 §7.6 真机验收）；
- WorkManager 在真实网络切换下的调度与退避；
- 生产后端域名、真实账号体系与跨设备同步；
- 场景跨设备同步的乱序/时钟漂移：服务端按字段时间戳判定新旧，本仓库只验证了时间戳递增的场景；真机多端同时编辑需要两台设备同时在线验证；
- `schedule` 的 DST 行为用 JVM `Calendar` 做了春季缺口/秋季重复单元测试，但未在真实时区切换的机型上跨天观察；
- 冷启动绝对耗时：下文 §11 的数字来自 Pixel_10a **模拟器**（软件渲染、debug 构建），只代表本机环境快照，不构成真机性能承诺；
- StrictMode 的磁盘/网络违规检测由真实 framework 完成，Robolectric 是空壳，`ColdStartNoMainThreadDiskIoTest` 必须连真机/模拟器执行。

## 12. 场景跨设备同步（v0.22.0）

> 需要后端 v0.20.0 / 契约 0.16.0 与两个已登录账号（A、B）。先把「我的 → 账号与数据」里的同步状态确认到「已同步」。

### 12.1 旧版本场景首次上传（不丢数据）

- 步骤：安装 v0.21.0，创建 3 个场景（例如「低 RSSI 通知」「指标越界通知」「连接设备」），再覆盖安装 v0.22.0。
- 预期：3 个场景全部还在；前两个场景在同步后变为「云端」状态；「连接设备」显示「仅本机」且不被上传；Room 迁移无崩溃。
- 失败判定：任一旧场景消失、全部显示「仅本机」、或启动报 `Room cannot verify the data integrity`。

### 12.2 跨设备拉取与字段级 LWW

- 步骤：A 端把场景改名为「A 改名」，等同步完成；B 端在同一场景上把开关停用，等同步完成；再回到 A 端同步。
- 预期：两端最终都是「A 改名 + 停用」；两端改的是不同字段，均被保留。
- 失败判定：改名被停用覆盖、停用被改名覆盖，或任一端出现「仅本机」。

### 12.3 离线编辑补传

- 步骤：A 端断网 → 新建 1 个场景、把已同步场景改名 → 恢复网络 → 手动同步。
- 预期：断网期间两条修改都保留并标「待上传」；恢复后新场景创建成功、旧场景通过 PUT 更新；`我的` 里待上传数归零。
- 失败判定：断网修改丢失、恢复后重复创建一条副本、或错误一直不消失。

### 12.4 软删除

- 步骤：A 端删除一个已同步场景；B 端同步后再删除另一个场景，回到 A 端同步。
- 预期：两端被删场景都从列表消失，不产生「复活」或重复；删除请求失败时场景仍保留并显示待上传。
- 失败判定：删除后另一端仍显示、删除失败却本地消失。

### 12.5 设备已移除

- 步骤：A 端删除场景引用的设备（设备页删除/移除），返回场景列表并触发一次该场景（可点手动运行）。
- 预期：场景行出现「设备已移除」标识；执行被跳过；场景执行记录新增一条失败记录，原因含「设备已移除」；场景本身不被级联删除。
- 失败判定：场景消失、列表无标识、执行静默成功、或没有失败记录。

### 12.6 定时（含 DST）

- 步骤：创建 `schedule` 场景（如 08:00、`Asia/Shanghai`、周一至周五），把系统时区切到有夏令时的地区（如 `America/New_York`），跨过春季 02:30 与秋季 01:30。
- 预期：每个计划日只执行一次；春季缺口顺延到 03:30 之后；秋季重复小时当天只执行一次；非 `daysOfWeek` 不执行。
- 失败判定：同一天执行两次、DST 当天漏执行、或周一/周日错位。

### 12.7 占位符

- 步骤：`notify` 标题填 `{device} 离线`、正文填 `{metric}={value}`；`log` 消息填 `{device} {metric} {value}`；分别由离线与指标越界触发。
- 预期：通知与执行记录显示真实设备名/指标/数值；整数不带 `.0`；未知占位符（如 `{foo}`）原样显示。
- 失败判定：显示字面 `{device}`、数值出现多余小数、或崩溃。

### 12.8 change_log 与未知 entity

- 步骤：在另一台已登录设备上改场景，A 端不点手动同步，等待周期同步；同时让服务端推送一条客户端不认识的 entity（可由后端联调环境注入）。
- 预期：场景变更被增量拉取并执行；未知 entity 被跳过，游标继续推进，后续场景变更不丢。
- 失败判定：同步卡住、游标回退、场景变更需重启才出现。

## 13. 会话生命周期、场景错误分级与契约补漏（v0.23.0）

> 前置：后端 v0.20.0 / 契约 0.16.0；至少两台设备（或一台设备 + 另一台模拟器）登录同一账号，用于会话吊销与跨端验证。

### 13.1 设备会话管理（当前会话 / 吊销其它会话）

- 步骤：进入「我的 → 账号与数据」卡片，点「设备会话」（`sessionsButton`）。
- 预期：弹出会话列表，每行显示创建时间与到期时间；当前会话带「当前设备」标记且没有吊销按钮；其它会话行有 ≥48dp 的「吊销」按钮（带 `contentDescription`）。
- 步骤：在第二台设备上登录同账号后回到第一台设备重开会话列表，点其它会话的「吊销」。
- 预期：该行立即从列表消失（或刷新后消失）；被吊销设备下一次请求收到 401 并走 13.3 的刷新/重登链路，不会静默换账号。
- 失败判定：列表为空、当前会话可被吊销、吊销后行不消失、或吊销后主设备也被登出。

### 13.2 退出当前会话 ≠ 删除账号

- 步骤：点「退出当前会话」，确认；随后在「我的」再次查看。
- 预期：本机 token 被清除并进入「需要重新登录」态；同步卡片显示需重新登录；本地设备、读数、场景数量与同步游标均不变；不出现「账号已删除」类文案。
- 步骤：对比「账号与数据 → 注销账号」入口，确认删除账号仍是独立的两次确认 + 一次性令牌流程。
- 预期：两个入口文案与确认步骤完全不同，退出不触发 `DELETE /me`。
- 失败判定：退出后本地数据被清空、退出与注销混为同一入口、或退出后自动新建匿名账号。

### 13.3 401 → 刷新 → 重放（含并发单飞）

- 步骤：后端可用时先完成一次成功同步；用管理接口或重启后端使当前 token 失效但在服务端仍保留 refresh 能力；在「我的」点「立即同步」。
- 预期：请求 401 后自动调用 `POST /auth/refresh`，拿到新 token 后**原请求原样重放**并成功，用户无感；同步卡片恢复正常；本地 `token` 已被原子替换（后续请求带新值）。
- 步骤：并发触发 5 个需要鉴权的请求（例如快速切页 + 手动同步 + 场景同步），使它们同时 401。
- 预期：抓包/日志中只出现 **1 次** `POST /auth/refresh`，其余请求等在锁内后用新 token 重放；不会出现「刷新后另一个请求拿旧 token 再刷新一次」。
- 失败判定：出现多次 refresh、重放请求仍用旧 token 死循环 401、或刷新成功后仍要求重新登录。

### 13.4 刷新失败 → 需重新登录且保留数据

- 步骤：让 `POST /auth/refresh` 明确返回 401/403（例如在服务端吊销会话或改签名密钥），再点「立即同步」。
- 预期：进入「需要重新登录」态；同步卡片提示保留本地数据；`我的` 弹出确认框给出两个明确选项——「用配对码恢复原账号」与「新建匿名账号」；选择前者会聚焦配对码输入框。
- 步骤：记录重登前的设备数、读数条数、场景数；关闭应用重开，再比对。
- 预期：数量完全不变；未点「新建匿名账号」之前本机绝不会自动调用 `/auth/anonymous`。
- 失败判定：401 后自动匿名登录、本地数据变少、确认框只有一个选项、或刷新失败仍反复重试刷新。

### 13.5 场景 4xx 终态与 429 延后

- 步骤：在「智能 → 场景」新建一个必定被服务端拒绝的场景（例如指标不在目录），触发同步。
- 预期：该场景行出现可读拒绝原因（中英双语），内容对应具体 `SCENE_*` 码（名称非法 / 冷却越界 / 条件非法 / 动作非法 / 设备不存在 / 指标不支持，或「场景不存在」「版本冲突」）；场景保持 `rejected` 终态，不再反复上传。
- 步骤：编辑该场景任一字段（改名 / 启停 / 冷却 / 条件 / 动作）后再次同步。
- 预期：状态重置为待上传并重新提交；若服务端已接受则转为已同步。
- 步骤：让服务端对场景接口返回 429 且带 `Retry-After`。
- 预期：到 `Retry-After` 之前不再重试；到点后自动补传，不在退避期间重复打服务端。
- 失败判定：4xx 一直挂在待上传、错误显示「未知错误」、编辑后不重试、或 429 被当作普通失败立刻重试。

### 13.6 导出失败原因

- 步骤：让 `GET /me/export/{id}` 返回 `status=failed` 且带 `failureReason`（例如「服务重启，任务中断」）。
- 预期：「我的 → 账号与数据」的导出状态直接展示服务端原因，而不是笼统的「导出失败，请稍后重试」；可重新发起导出。
- 失败判定：只显示通用提示、或原因与抓包中的 `failureReason` 不一致。

### 13.7 反馈详情与关闭（含 409）

- 步骤：在「我的 → 我的反馈记录」点任意一条反馈。
- 预期：进入详情，显示状态（已提交 / 已收到 / 已关闭）与状态说明、更新时间；不含联系方式与诊断信息。
- 步骤：对未关闭反馈点「关闭反馈」并确认。
- 预期：关闭成功，详情与列表状态变为「已关闭」。
- 步骤：对已关闭反馈再次尝试 `PATCH`（例如重试关闭）。
- 预期：服务端 409，界面显示「该反馈已关闭，不能重复关闭」这类明确文案，不是通用错误。
- 失败判定：详情打不开、列表状态不同步、409 落到「未知错误」。

### 13.8 Room v21 与 `device_missing` 列对齐

- 步骤：从 v0.22.0（`versionCode = 30`）覆盖安装 v0.23.0，先创建若干场景并保留一个引用已被移除设备的场景。
- 预期：启动无 `Room cannot verify the data integrity`；旧场景全部保留；`scenes` 表新增 `deviceMissing`（默认 0）与 `retryAfterAt`；引用已移除设备的场景显示「设备已移除」。
- 步骤：在另一台设备（iOS 或另一 Android）上删除设备后同步回来，确认 `deviceMissing` 来自服务端字段而非仅本地兜底。
- 预期：服务端返回 `deviceMissing=true` 时列表直接标注；服务端为 false 但本地缺设备时仍能本地兜底标注。
- 失败判定：迁移崩溃、旧场景丢失、列缺失、或只在本地重算而在跨端同步后不显示。

### 13.9 未验证部分（记录到验收表时标注 NOT VERIFIED）

## 14. 真 Postgres e2e 与界面截图（v0.28.1）

### 14.1 场景链路（真 Postgres）

- 步骤：`PJGOIOT_DIR=/tmp/pjgoiot-v022 ./scripts/e2e-postgres.sh`，执行 `postgres scenes contract upload lww soft delete and device missing`。
- 预期：首次上传返回非空 `remoteId` 且 `version>=1`；`GET /scenes` 按名称命中同一 `remoteId`；双端分别以更晚 `updatedAt` 修改 `name` 与 `enabled` 后两者都保留；引用设备被软删后场景 `deviceMissing=true` 且场景不被级联删除；场景软删后列表排除，owner 与陌生账号 `GET /scenes/{id}` 均 404。
- 失败判定：`remoteId` 未写回、LWW 丢字段、软删后仍出现在列表、`deviceMissing` 为 false、跨用户可读。

### 14.2 会话链路（真 Postgres）

- 步骤：同一用例内匿名登录、签发并接管第二个会话，执行 `GET/POST/DELETE /sessions` 与 `/auth/refresh`、`/auth/logout`。
- 预期：接管后 2 个会话且恰 1 个 `current`；吊销非当前会话后该 token 访问 `/my/devices` 返回 401、当前 token 200；`refresh` 返回新 token 且 TTL 存在，旧 token 401、新 token 200；`logout` 后 token 401；跨用户访问他人资源 404。
- 失败判定：旧 token 仍可用、吊销未生效、跨用户返回 200/403 而非 404。
